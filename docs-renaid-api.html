Rena ID API

Aggiungi «Accedi con Rena ID» al tuo sito o alla tua app in pochi minuti. Ricevi username e foto profilo dell'utente: mai la sua password, mai la sua email.

Come funziona

Rena ID usa lo standard OAuth 2.0 (Authorization Code con PKCE), lo stesso di «Accedi con Google». Servono quattro passaggi.

1

Registra la tua app

Qui sotto: scegli un nome e l'indirizzo di ritorno. Ottieni il tuo client_id (e il secret).

2

Manda l'utente a Rena ID

L'utente accede e approva la condivisione di username e foto.

3

Scambia il codice

Rena ID rimanda l'utente da te con un codice monouso. Il tuo server lo cambia con un token.

4

Leggi il profilo

Con il token ottieni id, username e foto, e crei la sessione sul tuo sito.

Registra la tua app

Registrare il tuo dominio richiede un minuto: serve solo dire a Rena ID a quale indirizzo può rimandare gli utenti dopo il login.

Le tue app

Non hai ancora registrato nessuna app.

Endpoint

Base URL: https://rena.altervista.org/oauth

GET /oauth/authorize.php

Apri questo indirizzo nel browser dell'utente (redirect, non una chiamata AJAX).

Parametro
response_type code
client_id Il client_id della tua app.
redirect_uri Uno degli URL di callback registrati, identico carattere per carattere.
state Valore casuale che generi tu e ricontrolli al ritorno (protegge da CSRF).
scope profile (opzionale, è l'unico disponibile).
code_challenge PKCE: base64url(SHA-256(code_verifier)). Obbligatorio per le app senza secret, consigliato sempre.
code_challenge_method S256

Ritorno: redirect_uri?code=…&state=… oppure redirect_uri?error=access_denied&state=… se l'utente annulla. Il codice vale 2 minuti e si usa una volta sola.

POST /oauth/token.php

Chiamalo dal tuo server (application/x-www-form-urlencoded).

Parametro
grant_type authorization_code
code Il codice ricevuto.
redirect_uri Lo stesso usato nel passaggio precedente.
client_id
client_secret Solo per i siti con backend (oppure HTTP Basic).
code_verifier Il valore casuale da cui hai calcolato code_challenge.

{"access_token":"…","token_type":"Bearer","expires_in":3600,"scope":"profile"}

GET /oauth/userinfo.php

Header: Authorization: Bearer ACCESS_TOKEN (il token dura 1 ora).

Campo
sub ID stabile dell'utente: usa questo per riconoscerlo ai login successivi.
username Nome utente.
profile_photo URL della foto profilo, oppure null.

{"sub":"123","username":"marco","profile_photo":"https://…"}

PHP

Buone pratiche

  • Controlla sempre lo state al ritorno: se non coincide con quello che avevi generato, scarta la richiesta.
  • Usa sub come identificatore dell'utente, non lo username.
  • Non collegare un account Rena a un tuo account esistente solo perché lo username è uguale: due persone diverse possono avere lo stesso nome su siti diversi.
  • Se scarichi la foto profilo, fallo dal tuo server e controlla che sia davvero un'immagine.
  • Non mettere mai il client_secret nel codice JavaScript di una pagina, in un'app mobile o su GitHub. Se è finito in pubblico, rigeneralo dalla lista delle tue app.

Errori comuni

Messaggio
Richiesta non valida client_id sconosciuto, oppure redirect_uri diverso da quelli registrati (anche solo per uno slash finale o http/https).
invalid_grant Codice scaduto (2 minuti), già usato, redirect_uri diverso o code_verifier sbagliato.
invalid_client client_id o client_secret errati.
invalid_token Token scaduto (1 ora) o header Authorization mancante.
